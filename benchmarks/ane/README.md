# ANE Feasibility Probe — Bounded Apple Neural Engine

Bounded, inspectable probe of Apple's private `AppleNeuralEngine.framework`
(`_ANEInMemoryModel` etc.) on this machine (M3 Ultra, Mac15,14, macOS 26.6.2),
adapted from [maderix/ANE](https://github.com/maderix/ANE) (MIT, pinned commit
`d91c9845c0784dec7753048954fc6d0e8411fe29`). See `LICENSE-ANE.md`.

Workload: **static FP16 1x1 convolution (linear) + ReLU** over a
`[1, 512, 1, 64]` tensor, pure private-ANE route (no CoreML fallback), with
structured bounded weights so the controller can compute an independent
float64 oracle and verify forward orientation element-by-element.

## Build

```bash

```

## Modes (native CLI)

```bash
./ane_probe --mode metadata --run-dir <dir>            # read-only introspection
./ane_probe --mode compile-and-run --run-dir <dir> --input <fp16.bin> \
    --weight identity|two-tap --channels 512 --spatial 64 --samples 3 --warmup 1 \
    --temp-policy isolated|system-model
```

Strict CLI validation: `--channels` in {256,512,1024}, `--spatial` in {16,64},
`--samples` in [1,100], `--warmup` in [0,10], `--compile-budget` in [1,8],
`--qos` must be 21, `--temp-policy` in {isolated, system-model}.

### Temp isolation policy

`--temp-policy` (default `isolated`) controls how the ANE compiler's per-model
temp dir is scoped:

- **isolated**: a preflight fails closed unless `NSTemporaryDirectory()` resolves
  to `<run-dir>/framework_tmp` (task-owned). Requires the launcher to set
  `TMPDIR=<run-dir>/framework_tmp` before Foundation starts.
- **system-model**: permits the Foundation actual temp root
  (`NSTemporaryDirectory()`); the preflight only requires it be a nonempty
  absolute directory. No env spoofing, no security change.

In BOTH policies the bridge **atomically creates the owned model temp dir**
`actualRoot/<hexId>` with mode `0700`, refusing `EEXIST`, before any writes,
and only then exposes it via `ane_bridge_last_tmpdir()`. The probe inventories
and copies **only that owned dir** (never the `NSTemporaryDirectory()` parent)
into `<run-dir>/compiler_artifacts` on success or failure (checked, refuses to
overwrite), and records the actual path + policy.

## Controller / harness

```bash
PYTHONPATH=. python3 benchmarks/ane/controller/ane_probe.py run \
    --results-dir benchmarks/ane/results/run-<date> \
    --cases identity,two-tap --channels 512 --spatial 64 --seed 1234 \
    --samples 10 --warmup 2 --compile-budget 2 --timeout 60 \
    --temp-policy system-model
```

The harness:
- generates deterministic **dyadic** fp16 inputs (multiples of 1/64, exactly
  representable), so identity (`1.0·x`) and two-tap (`0.5·x − 0.25·x[+1C]`)
  outputs are **exactly representable**; the comparison is EXACT
  (`atol=rtol=0`).
- independently builds the MIL text and weight blob and verifies the probe's
  generated bytes match (MIL/blob SHA-256 cross-check).
- computes the float64 oracle and verifies full-output equality.
- launches the probe with an isolated absolute `TMPDIR`
  (`<case>/framework_tmp`) by default; pass `--temp-policy system-model` to
  permit the Foundation actual temp root (used when the launch environment
  does not honor `TMPDIR` for `NSTemporaryDirectory()`).
- failfast: stops on first failure, never overwrites prior evidence, preserves
  raw stdout/stderr and the owned compiler artifacts.

## Workload / layout contract

- dtype fp16, tensor `[1, C, 1, S]`, weight `[C, C, 1, 1]` (out, in, 1, 1).
- MIL: `program(1.3)` / `func main<ios18>`; `conv` (1x1, groups=1, pad=valid,
  stride=1) then `relu`; weight loaded via `BLOBFILE(path =
  "@model_path/weights/weight.bin", offset = uint64(64))`.
- Weight blob byte layout (copied from upstream, not guessed):
  `64-byte global header (byte0=0x01, byte4=0x02)` + `64-byte chunk header
  (bytes64-67=0xEF 0xBE 0xAD 0xDE, byte68=0x01, uint32@72=data_size,
  uint32@80=128)` + row-major fp16 data at byte 128.
- IOSurface (matches upstream inmem_basic): width=row bytes, height=1,
  bytesPerElement=1, bytesPerRow=row bytes, pixelFormat=0; C512S64 →
  input/output 65536 logical bytes, stride padded to 16-byte alignment
  (65536 already aligned).
- Per-model compiler temp dir = `NSTemporaryDirectory()/<hexId>` (3×64-hex
  hashes joined by `_`), exactly as upstream.

## Timings / statuses recorded (separate)

`compile.elapsed_ms`, `compile.compile_attempts_after`, `load.elapsed_ms`,
`load.state_after`, `dispatch.per_eval_elapsed_ms` (+ mean), and
`transfer.write_input_ms` / `read_output_ms` — each compile/load/eval/transfer
call is checked for nil/NSError/NSException and never silently ignored. The
process-wide compile-attempt budget counts successes AND failures.

## Hardware / provenance (recorded)

- IORegistry: two `H11ANEIn` nodes (`H11ANE`, `H11ANE1`), each
  `NumANECores=16`, `ANEArchitectureTypeStr=h15g`, `ANEVersion=176`;
  runtime class name `H11` (not a literal M1-generation label).
- ANECompiler CFBundleVersion `9.509.0`; CoreML `3520.5.1`; macOS 26.6.2.
- Power-rail sampling unavailable (`sudo -n` required administrator authentication).

## Measured result and verification boundary

Both cases compiled, loaded and evaluated successfully in `system-model`
mode. All 32,768 outputs per case exactly matched an independent dense
float64 reference. With two warmups and ten timed evaluations, median
synchronous dispatch latency was **152.438 µs** for identity and
**131.958 µs** for two-tap. These times include host/IPC overhead and are
not a comparison against a vendor kernel.

[Results, hashes and independent verification](results/run-20260911-4/controller_verification.json)
and [the feasibility decision](../../docs/ane_feasibility.md) distinguish
runtime success from proof coverage. No compiled HWX executable was recovered:
the copied files contain MIL and weights, and the extra compile-only metadata
probe exposed tensor attributes but no executable location. Instruction and
memory-descriptor semantics remain unmodeled. No Lean proof of the emitted
ANE program is claimed, and there is no independent power-counter evidence.

OpenCode wrote the implementation under controller review, with at most two
concurrent worker requests. The controller executed and independently
verified the successful hardware runs. Earlier failures and source snapshots
are retained. Each new run requires a fresh results directory; existing model
temporary directories also cause a deliberate refusal rather than overwriting.
